# LAN Transfer 2.2.0

[Polski](#polski) · [English](#english)

---

## Polski

### Najważniejsze

Wraca wysyłanie **bez kodu parowania** – jako opcja, którą włącza odbiorca. W wersji 1.x każdy komputer w sieci mógł wysyłać pliki bez żadnego kodu; w 2.0.0 kod stał się obowiązkowy (poprawka bezpieczeństwa) i nie dało się go wyłączyć. Teraz można.

Protokół się nie zmienił (wersja 2): 2.2.0 współpracuje z 2.0.0 i 2.1.0. Starszy nadawca po prostu zawsze pokazuje okno kodu.

### Tryb bez kodu

- Nowa opcja **Ustawienia → Wymagaj kodu parowania** (domyślnie włączona). Zapisywana w `data\settings.json`.
- Gdy odbiorca ją wyłączy, każdy komputer z LAN Transfer w tej sieci może od razu wysyłać do niego pliki i przeglądać jego foldery – bez okna kodu. Transmisja nadal jest szyfrowana (TLS 1.3), a odcisk certyfikatu odbiorcy jest nadal przypinany.
- Odbiorca bez kodu ogłasza to w wykrywaniu; u nadawcy ma etykietę **bez kodu**, a kliknięcie łączy się od razu. Przy ręcznym połączeniu (adres IP) program najpierw próbuje bez kodu, a okno kodu pokazuje tylko wtedy, gdy odbiorca go wymaga.
- Dopóki kod jest wyłączony, w nagłówku okna odbiorcy widać pomarańczową plakietkę **Bez kodu**.
- Ponowne włączenie kodu działa od razu i rozłącza nadawców, którzy połączyli się bez kodu.
- Próba bez kodu u odbiorcy, który go wymaga, nie liczy się jako błędny kod (nie blokuje komputera).
- Wiersz poleceń: `LANTransferCLI.exe serve --no-code` (tylko dla tego uruchomienia), `send` bez `--code` działa z odbiorcą bez kodu. Zmienna `LANTRANSFER_REQUIRE_CODE=0/1` nadpisuje ustawienie.

> **Uwaga:** z wyłączonym kodem każdy w sieci może zapisywać pliki na tym komputerze i przeglądać jego foldery. Wyłączaj kod tylko w zaufanej sieci (dom, własne komputery).

### Weryfikacja pobranego pliku

```powershell
Get-FileHash .\LANTransfer-2.2.0-windows-amd64.zip -Algorithm SHA256
```

Porównaj wynik z plikiem `LANTransfer-2.2.0-windows-amd64.zip.sha256`.

## English

### Highlights

Sending **without a pairing code** is back – as an option the receiver turns on. In 1.x any computer on the network could send files without any code; in 2.0.0 the code became mandatory (a security fix) and could not be turned off. Now it can.

The protocol is unchanged (version 2): 2.2.0 works with 2.0.0 and 2.1.0. An older sender simply always shows the code dialog.

### No-code mode

- New option **Settings → Require pairing code** (on by default), saved in `data\settings.json`.
- When the receiver turns it off, any computer running LAN Transfer on the network can send files to it and browse its folders right away, without the code dialog. Traffic is still encrypted (TLS 1.3) and the receiver's certificate fingerprint is still pinned.
- A receiver without a code announces it in discovery; the sender shows a **no code needed** badge and connects on click. For a manual connection (IP address) the app first tries without a code and shows the code dialog only if the receiver requires one.
- While the code is off, the receiver's window shows an orange **No code** badge in the header.
- Turning the code back on takes effect at once and disconnects senders that connected without a code.
- Trying without a code on a receiver that requires one does not count as a wrong code (no lockout).
- Command line: `LANTransferCLI.exe serve --no-code` (this run only); `send` without `--code` works with a no-code receiver. `LANTRANSFER_REQUIRE_CODE=0/1` overrides the setting.

> **Note:** with the code off, anyone on the network can save files on this computer and browse its folders. Turn the code off only on a network you trust (home, your own computers).

### Verify the download

```powershell
Get-FileHash .\LANTransfer-2.2.0-windows-amd64.zip -Algorithm SHA256
```

Compare the result with `LANTransfer-2.2.0-windows-amd64.zip.sha256`.
