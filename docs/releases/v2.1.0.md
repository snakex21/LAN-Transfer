# LAN Transfer 2.1.0

[Polski](#polski) · [English](#english)

## Polski

### Najważniejsze

Interfejs LAN Transfer jest teraz dostępny w 30 językach – tych samych co README: angielski, polski, niemiecki, francuski, hiszpański, włoski, portugalski, niderlandzki, szwedzki, norweski, duński, fiński, czeski, słowacki, węgierski, rumuński, turecki, indonezyjski, malajski, wietnamski, rosyjski, ukraiński, bułgarski, grecki, arabski, hebrajski, hindi, chiński, japoński i koreański.

Protokół się nie zmienił (wersja 2): 2.1.0 współpracuje z 2.0.0 i nie trzeba aktualizować obu komputerów jednocześnie.

### Język interfejsu

- Przy pierwszym uruchomieniu program używa języka wyświetlania Windows (pierwszego obsługiwanego z listy języków użytkownika). Jeśli język Windows nie jest obsługiwany, interfejs jest po angielsku.
- Nowy przycisk **Ustawienia** (koło zębate w prawym górnym rogu) pozwala wybrać język. Okno, jego tytuł i wszystkie komunikaty zmieniają się od razu, bez restartu. Wybór jest zapisywany w `data\settings.json`; **Automatycznie (Windows)** wraca do języka systemu.
- Liczby, rozmiary, prędkości, czasy, daty i formy liczby mnogiej („1 plik”, „3 pliki”, „5 plików”) są formatowane według reguł wybranego języka (Intl / CLDR).
- Arabski i hebrajski mają lustrzany układ od prawej do lewej; ścieżki, adresy IP, kody parowania i odciski certyfikatów są zawsze wyświetlane od lewej do prawej.
- Komunikaty odbiorcy (np. brak miejsca na dysku, błędna suma SHA-256, błędny kod parowania) są wyświetlane w języku nadawcy, a nie odbiorcy: program przesyła klucz komunikatu z parametrami zamiast gotowego tekstu.
- `LANTransferCLI.exe` (pomoc, postęp, komunikaty) używa tego samego języka. Zmienna `LANTRANSFER_LANG` (np. `LANTRANSFER_LANG=de`) wymusza język okna i wiersza poleceń.
- Tytuły systemowych okien wyboru plików i folderów są w języku programu.

### Dla programistów

- Teksty są w `locales/ui.<kod>.json` ze stałymi kluczami; polski jest językiem źródłowym, angielski – zapasowym.
- `tools/check_i18n.py` (także w CI) sprawdza w 30 plikach: zgodność kluczy, placeholdery i formaty, kategorie liczby mnogiej każdego języka, brak pustych wartości, zachowanie literałów technicznych (`SHA-256`, `UAC`, flagi CLI) oraz brak pozostałości polskiego tekstu.
- Test Go sprawdza, że każdy klucz użyty w kodzie Go, w skryptach i w HTML okna istnieje we wszystkich językach (i że żaden klucz nie jest zbędny), a reguły liczby mnogiej w Go są zgodne z `Intl.PluralRules`.
- Odpowiedź błędu protokołu ma opcjonalne pola `key` i `params`; pole `error` zawiera tekst po angielsku dla starszych wersji.

### Weryfikacja pobranego pliku

```powershell
Get-FileHash .\LANTransfer-2.1.0-windows-amd64.zip -Algorithm SHA256
```

Porównaj wynik z plikiem `LANTransfer-2.1.0-windows-amd64.zip.sha256`.

## English

### Highlights

The LAN Transfer interface is now available in 30 languages, the same as the README: English, Polish, German, French, Spanish, Italian, Portuguese, Dutch, Swedish, Norwegian, Danish, Finnish, Czech, Slovak, Hungarian, Romanian, Turkish, Indonesian, Malay, Vietnamese, Russian, Ukrainian, Bulgarian, Greek, Arabic, Hebrew, Hindi, Chinese, Japanese and Korean.

The protocol is unchanged (version 2): 2.1.0 works with 2.0.0, so the two computers do not have to be updated at the same time.

### Interface language

- On the first start the app uses the Windows display language (the first supported one in the user's language list). If Windows uses a language that is not supported, the interface is in English.
- A new **Settings** button (the gear in the top-right corner) lets you pick the language. The window, its title and all messages switch immediately, without a restart. The choice is saved in `data\settings.json`; **Automatic (Windows)** goes back to the system language.
- Numbers, sizes, speeds, durations, dates and plural forms ("1 file", "3 files"; in Polish "1 plik", "3 pliki", "5 plików") follow the rules of the chosen language (Intl / CLDR).
- Arabic and Hebrew use a mirrored right-to-left layout; paths, IP addresses, pairing codes and certificate fingerprints are always shown left-to-right.
- Messages from the receiver (for example not enough disk space, a SHA-256 mismatch, a wrong pairing code) are shown in the sender's language, not the receiver's: the program sends a message key with parameters instead of finished text.
- `LANTransferCLI.exe` (help, progress, messages) uses the same language. The `LANTRANSFER_LANG` variable (for example `LANTRANSFER_LANG=de`) forces the language of the window and the command line.
- The native file and folder pickers have titles in the program's language.

### For developers

- The texts live in `locales/ui.<code>.json` with stable keys; Polish is the source language, English the fallback.
- `tools/check_i18n.py` (also in CI) checks the 30 files: identical keys, placeholders and formats, the plural categories of every language, no empty values, technical literals kept (`SHA-256`, `UAC`, CLI flags) and no leftover Polish text.
- A Go test checks that every key used in the Go code, the scripts and the HTML of the window exists in every language (and that no key is unused), and that the Go plural rules match `Intl.PluralRules`.
- The protocol error response has optional `key` and `params` fields; `error` holds English text for older versions.

### Verify the download

```powershell
Get-FileHash .\LANTransfer-2.1.0-windows-amd64.zip -Algorithm SHA256
```

Compare the result with `LANTransfer-2.1.0-windows-amd64.zip.sha256`.
