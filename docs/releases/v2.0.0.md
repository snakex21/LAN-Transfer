# LAN Transfer 2.0.0

[Polski](#polski) · [English](#english)

---

## Polski

### Najważniejsze

Wersja 2.0.0 to przebudowa protokołu i interfejsu z naciskiem na bezpieczeństwo. Program nadal jest jednym przenośnym plikiem EXE dla Windows 10/11.

> **ZMIANA NIEZGODNA WSTECZ.** Wersja 2 nie współpracuje z wersją 1 (nowy protokół, HTTPS, parowanie). **Zaktualizuj program na obu komputerach.** Odbiorca przy każdym uruchomieniu tworzy nowy kod i certyfikat, więc **po restarcie odbiorcy trzeba sparować się ponownie**.

### Poprawki bezpieczeństwa

- **Wysyłanie bez zgody** – w 1.x dowolny komputer w sieci mógł zapisać pliki na odbiorcy. Teraz wysyłanie i przeglądanie folderów wymaga tokenu uzyskanego 6-cyfrowym kodem parowania (blokada po 5 błędnych kodach z jednego komputera, zmiana kodu po 30 błędach łącznie).
- **Dowolny folder docelowy** – pole „destination” pozwalało niesparowanemu nadawcy pisać do dowolnego istniejącego folderu (np. Autostart). Teraz tylko sparowani nadawcy i tylko istniejące foldery podane ścieżką bezwzględną.
- **Przeglądanie dysków** – `/api/browse` pokazywało każdemu wszystkie dyski i foldery. Teraz tylko sparowanym.
- **Niebezpieczne nazwy** – nazwy typu `plik.txt:strumień` tworzyły alternatywne strumienie NTFS (ADS), `NUL` po cichu gubił dane; `..`, ścieżki bezwzględne i nazwy zarezerwowane (`CON`, `NUL`, `COM1`…) są odrzucane.
- **Nadpisywanie** – odebrane pliki nadpisywały istniejące; teraz powstaje `nazwa (1).ext` / `Folder (1)`.
- **Ruch bez szyfrowania** – HTTP zastąpiono HTTPS.

### Parowanie, TLS i odcisk certyfikatu

- TLS 1.3 z certyfikatem generowanym przy każdym uruchomieniu.
- Odcisk certyfikatu jest pokazywany na obu ekranach, zapamiętywany przy parowaniu i sprawdzany przy każdym połączeniu.
- **Nowy kod** unieważnia stary kod i wszystkie parowania.

### Transfer

- Wznawianie przerwanych i anulowanych transferów od miejsca przerwania.
- Suma SHA-256 każdego pliku; plik dostaje docelową nazwę dopiero po zgodności sumy, a dane w trakcie są w ukrytym `.lantransfer-partial`.
- Foldery wysyłane plik po pliku (struktura zachowana), do 4 plików równolegle.
- Postęp każdego pliku, prędkość, czas do końca, anulowanie, historia; sprawdzanie wolnego miejsca.

### Wydajność

Pomiary na jednym komputerze przez 127.0.0.1 (bez ograniczeń sieci; w prawdziwej sieci 1 Gb/s limitem jest łącze, ok. 110 MB/s):

| Test | 1.x | 2.0.0 |
|---|---|---|
| benchmark 1 GiB (`go test -bench`, 2 serie) | 449 / 535 MB/s (HTTP bez szyfrowania) | 952 / 861 MB/s (TLS + SHA-256) |
| CLI, plik 3 GB, 3 próby | – | 879–900 MB/s |
| wiele małych plików (benchmark) | 7,9–9,2 MB/s | 3,9–4,0 MB/s |

Duże pliki są ponad 1,6× szybsze mimo szyfrowania (odczyt, SHA-256, TLS i zapis działają równolegle). Bardzo wiele małych plików jest wolniejszych niż w 1.x, bo każdy plik ma osobne żądanie, sumę i bezpieczne przeniesienie na miejsce.

### Zapora Windows

- Nowe reguły `LAN Transfer 2 Discovery (UDP)` i `LAN Transfer 2 Transfer (TCP)` działają tylko w profilach **Prywatny** i **Domena** (`profile=private,domain`) i tylko dla lokalnej podsieci. W sieci oznaczonej jako Publiczna porty nie są otwierane.
- Jeśli program znajdzie reguły z 1.x (dla wszystkich profili, także Publicznego), pokaże baner z propozycją ich zastąpienia. Nic nie zmienia się bez kliknięcia **Zaktualizuj reguły** i potwierdzenia UAC.

### Inne

- Wersja w stopce okna, w `LANTransferCLI.exe version` i we właściwościach pliku EXE; ikona programu.
- Licencja MIT.

### Jak sparować

1. Uruchom LAN Transfer 2.0.0 na obu komputerach.
2. Na komputerze wysyłającym kliknij odbiorcę na liście (albo **Połącz ręcznie** i wpisz jego IP).
3. Wpisz 6-cyfrowy kod widoczny w prawym górnym rogu okna odbiorcy.
4. Porównaj odcisk certyfikatu w oknie parowania z odciskiem na ekranie odbiorcy. Jeśli się różnią, przerwij.
5. Kliknij **Sparuj**. Po restarcie odbiorcy powtórz parowanie.

## English

### Highlights

2.0.0 is a rework of the protocol and the user interface with a focus on security. The program is still a single portable EXE for Windows 10/11.

> **BREAKING CHANGE.** Version 2 is not compatible with version 1 (new protocol, HTTPS, pairing). **Update the program on both computers.** The receiver creates a new code and certificate every time it starts, so **pair again after the receiver restarts**.

### Security fixes

- **Unauthenticated upload**: in 1.x any computer on the network could write files to the receiver. Sending and folder browsing now require a token obtained with the 6-digit pairing code (lockout after 5 wrong codes from one computer, the code changes after 30 failures in total).
- **Arbitrary destination**: the "destination" field let an unpaired sender write into any existing folder (for example Startup). Now only paired senders, and only existing folders given as absolute paths.
- **Folder browsing**: `/api/browse` listed every drive and folder to anyone. Now paired senders only.
- **Unsafe names**: names like `file.txt:stream` created NTFS alternate data streams (ADS) and `NUL` silently discarded data; `..`, absolute paths and reserved names (`CON`, `NUL`, `COM1`…) are rejected.
- **Overwriting**: received files replaced existing ones; now `name (1).ext` / `Folder (1)` is created.
- **Plain traffic**: HTTP was replaced with HTTPS.

### Pairing, TLS and fingerprint

- TLS 1.3 with a certificate generated at every start.
- The certificate fingerprint is shown on both screens, pinned during pairing and checked on every connection.
- **Nowy kod** (New code) invalidates the old code and all pairings.

### Transfer

- Interrupted and cancelled transfers resume where they stopped.
- SHA-256 of every file; a file gets its final name only after the checksum matches, and data in progress stays in the hidden `.lantransfer-partial` folder.
- Folders are sent file by file (structure kept), up to 4 files in parallel.
- Per-file progress, speed, time remaining, cancel, history; free space is checked.

### Performance

Measured on one computer over 127.0.0.1 (no network limits; on a real 1 Gb/s network the link is the limit, about 110 MB/s):

| Test | 1.x | 2.0.0 |
|---|---|---|
| 1 GiB benchmark (`go test -bench`, 2 rounds) | 449 / 535 MB/s (plain HTTP) | 952 / 861 MB/s (TLS + SHA-256) |
| CLI, 3 GB file, 3 runs | – | 879–900 MB/s |
| many small files (benchmark) | 7.9–9.2 MB/s | 3.9–4.0 MB/s |

Large files are more than 1.6× faster despite encryption (reading, SHA-256, TLS and writing run in parallel). Very many small files are slower than in 1.x because every file has its own request, checksum and safe rename.

### Windows Firewall

- The new rules `LAN Transfer 2 Discovery (UDP)` and `LAN Transfer 2 Transfer (TCP)` apply only to the **Private** and **Domain** profiles (`profile=private,domain`) and only to the local subnet. On a network marked Public the ports are not opened.
- If the app finds the 1.x rules (all profiles, Public included), it shows a banner offering to replace them. Nothing changes until you click **Zaktualizuj reguły** (Update rules) and confirm the UAC prompt.

### Other

- Version in the window footer, in `LANTransferCLI.exe version` and in the EXE file properties; program icon.
- MIT license.

### How to pair

1. Start LAN Transfer 2.0.0 on both computers.
2. On the sending computer click the receiver in the list (or **Połącz ręcznie** / Connect manually and enter its IP).
3. Type the 6-digit code shown in the top-right corner of the receiver's window.
4. Compare the certificate fingerprint in the pairing dialog with the one on the receiver's screen. If they differ, stop.
5. Click **Sparuj** (Pair). Pair again after the receiver restarts.

### Verify the download

```powershell
Get-FileHash .\LANTransfer-2.0.0-windows-amd64.zip -Algorithm SHA256
```

Compare the result with `LANTransfer-2.0.0-windows-amd64.zip.sha256`.
